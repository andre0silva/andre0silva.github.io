Azure: rede hub-spoke

Como montar uma rede central (hub) com firewall e VPN e ligar as redes das aplicações (spokes), com os nomes de sub-rede que o Azure exige.

AzureVNetHub-spokeNSGAzure Firewall

00Antes de começar

Plenonível
1 hubN spokes
Peeringnão é transitivo
10.100.0.0/16faixa do exemplo

No hub ficam os serviços compartilhados: firewall, gateway de VPN ou ExpressRoute e Bastion. Cada aplicação ganha sua própria VNet (spoke), ligada ao hub por peering.

01Endereçamento do exemplo

VNet ou sub-redeFaixaObservação
vnet-hub-prd10.100.0.0/22Rede central
GatewaySubnet10.100.0.0/27Nome obrigatório; recebe o gateway de VPN
AzureFirewallSubnet10.100.1.0/26Nome obrigatório; /26 é o mínimo
AzureBastionSubnet10.100.2.0/26Nome obrigatório; /26 ou maior
vnet-erp-prd (spoke)10.100.4.0/22Aplicação ERP
snet-app10.100.4.0/24Servidores de aplicação
snet-dados10.100.5.0/24Banco de dados e private endpoints

Reserve a faixa da cloud no plano de endereçamento da empresa para não sobrepor redes do escritório.

02Criar com Azure CLI

# Hub com a GatewaySubnet
az network vnet create -g rg-rede-hub-prd -n vnet-hub-prd -l brazilsouth \
  --address-prefixes 10.100.0.0/22 --subnet-name GatewaySubnet --subnet-prefixes 10.100.0.0/27

# Spoke da aplicação
az network vnet create -g rg-erp-prd -n vnet-erp-prd -l brazilsouth \
  --address-prefixes 10.100.4.0/22 --subnet-name snet-app --subnet-prefixes 10.100.4.0/24

# Peering nos dois sentidos (o hub compartilha o gateway com o spoke)
az network vnet peering create -g rg-rede-hub-prd -n hub-para-erp --vnet-name vnet-hub-prd \
  --remote-vnet <ID da vnet-erp-prd> --allow-vnet-access --allow-forwarded-traffic --allow-gateway-transit
az network vnet peering create -g rg-erp-prd -n erp-para-hub --vnet-name vnet-erp-prd \
  --remote-vnet <ID da vnet-hub-prd> --allow-vnet-access --allow-forwarded-traffic --use-remote-gateways

A opção de usar o gateway remoto só funciona depois que o gateway de VPN existir no hub.

az network nsg rule create -g rg-erp-prd --nsg-name nsg-snet-app -n permitir-https-escritorio \
  --priority 100 --direction Inbound --access Allow --protocol Tcp \
  --source-address-prefixes 10.1.0.0/16 --destination-port-ranges 443
Peering não é transitivo

Dois spokes ligados ao mesmo hub não se falam diretamente. Para isso, o tráfego precisa passar pelo firewall do hub com rotas definidas pelo usuário.

00Antes de começar

Servidor verde e cliente reclamando é a situação clássica. Monitoramento sintético responde "funciona agora, de fora?"; RUM responde "como foi para os usuários reais?". Os dois juntos fecham a lacuna.

01Monitoramento sintético

TipoTestaExemplo
Disponibilidade (ping/HTTP)O serviço respondePágina inicial retorna 200 em < 2 s
APIContrato e tempo de respostaAutenticar e consultar pedido
Navegador (scripted)Jornada completaLogin, busca, carrinho, pagamento em sandbox
Certificado e DNSVencimento e resoluçãoAlerta 30 dias antes do vencimento
  1. Escolha as jornadasAs 5 a 10 que geram receita ou atendem obrigação legal.
  2. Escreva scripts robustosSeletores estáveis, dados de teste dedicados, limpeza após o teste.
  3. OrigensPelo menos três locais externos (regiões e operadoras diferentes) e um interno.
  4. AlertasFalha em 2 de 3 locais por 2 rodadas seguidas, para evitar alarme por problema local.
  5. FerramentasGrafana k6/Synthetic Monitoring, Playwright, Azure Application Insights, Datadog, Uptime Kuma para o básico.

02RUM (usuário real)

  • Script leve no front-end ou SDK mobile coleta tempo de carregamento, erros de JavaScript, chamadas de API e dispositivo.
  • Core Web Vitals no percentil 75: LCP ≤ 2,5 s, INP ≤ 200 ms, CLS ≤ 0,1.
  • Segmentar por página, dispositivo, navegador, região e versão de deploy.
  • Ligar a sessão do usuário ao trace do back-end (propagação de contexto) para achar a causa.

03Privacidade

  • Não coletar conteúdo de campos de formulário, CPF, cartão ou dados de saúde.
  • Mascaramento padrão em gravação de sessão, se usada.
  • Base legal e aviso no banner de cookies conforme LGPD; amostragem quando possível.

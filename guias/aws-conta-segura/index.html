AWS: conta segura desde o primeiro dia

As configurações que fecham os incidentes mais comuns em contas AWS: root exposto, chaves de acesso vazadas, bucket público e conta sem trilha de auditoria.

01Usuário root

  • MFA no root, de preferência chave de segurança física.
  • Nenhuma chave de acesso no root.
  • E-mail do root numa caixa compartilhada da TI, não na de uma pessoa.
  • Root só para as poucas tarefas que exigem root; o dia a dia usa outras identidades.
# AccountMFAEnabled = 1 e AccountAccessKeysPresent = 0 é o esperado
aws iam get-account-summary

02Identidades e contas

PráticaPor quê
AWS Organizations com contas separadas (segurança, logs, produção, testes)Isola o impacto de erros e incidentes

03Registro e detecção

# Trilha do CloudTrail (de preferência uma trilha da organização em todas as regiões)
aws cloudtrail describe-trails

# Ligar o GuardDuty na região
aws guardduty create-detector --enable

# Bloquear acesso público ao S3 em toda a conta
aws s3control put-public-access-block --account-id 111122223333 \
  --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# Criptografia padrão de discos EBS (configuração por região)
aws ec2 enable-ebs-encryption-by-default

AWS Config e Security Hub completam o quadro: registram mudanças de configuração e consolidam achados de segurança.

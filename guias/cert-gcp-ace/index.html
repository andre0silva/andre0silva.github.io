Google Cloud Associate Cloud Engineer: trilha de preparação

00Antes de começar

O guia do ACE foi refeito em 30 de junho de 2026: agora são quatro seções, com mais peso em operação e novos objetivos sobre ferramentas de IA e nomes de produtos atualizados. Estudar por material antigo de cinco seções é o erro mais comum.

FormatoMúltipla escolha e múltipla seleção

Nomes de produtos mudaram

Cloud Functions agora é Cloud Run functions, e o guia cita Cloud NGFW e novos nomes de produtos de IA. Use a documentação atual.

01Seções e pesos

SeçãoPesoO que dominar
1 · Preparar o ambiente~20%Hierarquia de recursos, políticas da organização, IAM, Cloud Identity, APIs, cotas, Cloud Asset Inventory, Workforce Identity Federation, contas de faturamento, orçamentos e exportação
2 · Planejar e implantar~30%Escolha entre Compute Engine, GKE, Cloud Run e functions; MIGs, Spot VMs, OS Login; storage e bancos; VPC, Shared VPC, firewall e Cloud NGFW, conectividade, balanceadores; IaC (Terraform, Config Connector, Helm) e ferramentas de IA
3 · Operar~30%VMs, snapshots e imagens, GKE e autoscaling, Cloud Run e divisão de tráfego, storage (lifecycle, CMEK, backup), rede (sub-redes, IPs, rotas, Cloud DNS, Cloud NAT), monitoramento e logging (alertas, logs de auditoria e fluxo, roteadores de logs, Ops Agent, Managed Prometheus)
4 · Acesso e segurança~20%Políticas IAM, herança, tipos de função, funções personalizadas, contas de serviço, impersonation, credenciais de curta duração, Workload Identity Federation

02Plano de 6 semanas

  1. Semana 1 · Ambiente e IAMOrganização, pastas, projetos, IAM, contas de serviço, faturamento e orçamentos. Instale e configure o gcloud.
  2. Semana 2 · ComputaçãoCompute Engine, MIGs com autoscaling, Spot, Cloud Run, Cloud Run functions, GKE (Autopilot e Standard).
  3. Semana 3 · Storage e dadosCloud Storage (classes, lifecycle), Cloud SQL, Spanner, Firestore, Bigtable, BigQuery, Pub/Sub, Memorystore.
  4. Semana 4 · RedeVPC, sub-redes, firewall e políticas de NGFW, Shared VPC, peering, Cloud NAT, Cloud DNS, balanceadores, VPN e Interconnect.
  5. Semana 5 · OperaçãoCloud Monitoring, Logging, roteadores e buckets de log, Ops Agent, IaC com Terraform.
  6. Semana 6 · Revisão e simuladosQuestões de exemplo oficiais, simulados e laboratórios dos pontos fracos.

03Pontos que mais pegam

Escolha de computação

NecessidadeEscolha típica
Controle total da VM, software legadoCompute Engine
Contêiner sem gerenciar cluster, escala a zeroCloud Run
Função disparada por eventoCloud Run functions
Orquestração Kubernetes completaGKE (Autopilot para menos operação)
Lote tolerante a interrupção, baratoSpot VMs

Escolha de dados

NecessidadeEscolha típica
Relacional regional (MySQL, PostgreSQL, SQL Server)Cloud SQL
Relacional global com escala horizontalSpanner
Documentos para apps web e mobileFirestore
Séries temporais e alto volume de escritaBigtable
Data warehouse e SQL analíticoBigQuery
Mensageria assíncronaPub/Sub

IAM

  • Política IAM é herdada: organização → pasta → projeto → recurso. Permissão concedida no alto não é removida embaixo (exceto com políticas de negação).
  • Funções básicas (Owner, Editor, Viewer) são amplas demais para produção; prefira predefinidas ou personalizadas.
  • Contas de serviço: evite chaves; use impersonation, credenciais de curta duração e Workload Identity Federation.

Comandos que vale saber

  • gcloud config set project ID e gcloud config configurations para trocar contexto.
  • gcloud compute instances create, gcloud container clusters get-credentials, gcloud run deploy.
  • gcloud projects add-iam-policy-binding e gcloud iam service-accounts.
  • gsutil está sendo substituído por gcloud storage.

04Laboratórios

  1. Projeto e faturamentoProjeto novo, orçamento com alerta, APIs habilitadas pelo gcloud.
  2. Web escalávelTemplate de instância, MIG regional com autoscaling e balanceador HTTP(S).
  3. Cloud RunImplante um contêiner, divida o tráfego 90/10 entre revisões.
  4. RedeVPC personalizada, regra de firewall por tag de rede, Cloud NAT para VMs sem IP público.
  5. IAMConta de serviço com função mínima e uso via impersonation, sem chave.
  6. ObservabilidadeOps Agent em uma VM, alerta de uso de CPU e roteador de logs para um bucket.

05Armadilhas comuns

  • Material antigo com cinco seções e nomes de produtos desatualizados.
  • Confundir regras de firewall por tag com por conta de serviço.
  • Esquecer que Cloud NAT só atende saída; entrada exige IP público ou balanceador.

07Autoavaliação

Questões autorais. Clique na alternativa para ver a resposta.

1. Uma API em contêiner precisa escalar a zero quando ociosa, sem gerenciar cluster. Qual serviço?

Cloud Run escala por requisição, inclusive a zero.

2. VMs sem IP público precisam baixar atualizações da internet. O que configurar?

Cloud NAT permite saída sem IP público.

3. Um papel concedido na pasta se aplica aos projetos dentro dela?

IAM é herdado na hierarquia.

4. Como uma aplicação fora do Google Cloud acessa APIs sem chave de conta de serviço?

Federação troca credencial externa por token de curta duração.

5. Banco relacional com consistência forte e escala global. Qual escolher?

Spanner é relacional distribuído globalmente.

6. Como enviar 10% do tráfego para uma nova versão no Cloud Run?

Cloud Run divide tráfego entre revisões.

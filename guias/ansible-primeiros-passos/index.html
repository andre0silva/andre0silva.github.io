01Instalação e inventário

python3 -m pip install --user ansible
ansible --version

Arquivo inventory.ini:

[web]
web01 ansible_host=10.1.20.11
web02 ansible_host=10.1.20.12

[web:vars]
ansible_user=ansible
# Testar a conexão com todos os servidores do grupo
ansible web -i inventory.ini -m ansible.builtin.ping

02Primeiro playbook

Arquivo web.yml, para Ubuntu:

- name: Servidores web padronizados
  hosts: web
  become: true
  tasks:
    - name: Atualizar cache e pacotes
      ansible.builtin.apt:
        update_cache: true
        upgrade: dist

    - name: Instalar nginx
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Garantir nginx ativo na inicialização
      ansible.builtin.service:
        name: nginx
        state: started
        enabled: true
# Simular sem alterar nada e mostrar as diferenças
ansible-playbook -i inventory.ini web.yml --check --diff

# Executar de verdade
ansible-playbook -i inventory.ini web.yml

Rode o playbook duas vezes: na segunda, as tarefas devem aparecer como ok e não como changed. Isso é idempotência.

03E o Windows?

O Ansible também gerencia Windows pelas coleções ansible.windows e community.windows, conectando por WinRM ou SSH. O nó de controle continua sendo Linux.

04Boas práticas

  • Playbooks e inventário versionados no Git, com revisão antes de rodar em produção.
  • Senhas e chaves no Ansible Vault (ansible-vault create segredos.yml), nunca em texto puro.
  • Sempre --check --diff antes de mudanças em produção, e por grupos pequenos (--limit).
  • Nomes completos de módulos (ansible.builtin.apt) e validação com ansible-lint.
  • Quando o playbook crescer, separe em roles.

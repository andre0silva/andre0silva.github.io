03Pontos que mais pegam

Identidade e governança

  • RBAC: Owner (tudo, inclusive conceder acesso), Contributor (tudo, menos conceder acesso), Reader, User Access Administrator. Herança de cima para baixo.
  • Funções do Entra ID (administrar o diretório) são diferentes de funções RBAC do Azure (administrar recursos).
  • Lock ReadOnly pode quebrar operações que parecem leitura, como listar chaves de storage.

Storage

  • SAS de serviço/conta assinada com chave x SAS de delegação de usuário assinada com Entra ID (preferível).
  • Política de acesso armazenada permite revogar SAS sem trocar a chave.
  • Mudar redundância e camadas tem implicações de custo e tempo; archive exige reidratação.

Computação

  • Conjunto de disponibilidade (domínios de falha e atualização no mesmo data center) x zonas de disponibilidade (data centers diferentes).
  • Slots de deployment do App Service exigem plano Standard ou superior; swap troca as configurações marcadas como "slot setting" de forma diferente.

Rede

  • NSG avalia regras por prioridade (menor número primeiro). Regras efetivas mostram o resultado de NSG da sub-rede + NIC.
  • Peering não é transitivo: A↔B e B↔C não fazem A falar com C.
  • Service endpoint mantém IP público do serviço, restrito à VNet; private endpoint dá IP privado na VNet e exige DNS privado.

Monitoramento e backup

  • KQL básico: where, summarize, project, render.
  • Recovery Services vault (VMs, SQL em VM, Files) x Backup vault (discos, blobs, PostgreSQL); Site Recovery para replicar VMs entre regiões.

04Laboratórios

  1. GovernançaManagement group, Policy de tags obrigatórias com efeito de negar, lock em resource group, budget com alerta.
  2. StorageStorage account com firewall para uma VNet, SAS de delegação de usuário, lifecycle para cool após 30 dias.
  3. BicepArquivo Bicep que cria VNet com duas sub-redes e uma VM; implante com az deployment group create.
  4. RedeDuas VNets com peering, NSG bloqueando RDP da internet, acesso pelo Bastion, private endpoint para a storage.
  5. MonitoramentoAlerta de CPU com action group por e-mail, consulta KQL em logs da VM, Connection Monitor.
  6. Backup e DRBackup de VM com restauração de arquivo e replicação com Site Recovery para outra região.

05Armadilhas comuns

  • Confundir funções do Entra ID com RBAC do Azure.
  • Esquecer que mover VM entre regiões é diferente de mover entre resource groups.
  • Questões de rede com tabela de regras: calcule a ordem por prioridade, não pela ordem em que aparecem.

07Autoavaliação

Questões autorais. Clique na alternativa para ver a resposta.

1. Um usuário precisa gerenciar VMs de um resource group, mas não pode conceder acesso a outras pessoas. Qual função?

Contributor gerencia recursos sem atribuir funções.

2. VNet A tem peering com B e B com C. A consegue falar com C?

Peering não é transitivo.

3. Qual opção dá à storage account um IP privado dentro da VNet?

Private endpoint cria uma interface com IP privado.

4. Como revogar várias SAS emitidas sem trocar a chave da conta?

SAS vinculadas a uma política armazenada são revogadas ao alterar ou remover a política.

5. Um NSG tem regra 100 negando RDP e regra 200 permitindo RDP. O RDP passa?

Menor prioridade numérica vence.

6. Qual serviço replica VMs para outra região para DR?

Site Recovery orquestra replicação e failover.

7. Qual lock impede excluir, mas permite alterar o recurso?

CanNotDelete bloqueia só exclusão.

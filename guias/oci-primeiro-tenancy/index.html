01Estrutura de compartimentos

tenancy (raiz: só administração)
├── cmp-rede          (VCNs, DRG, gateways)
├── cmp-seguranca     (Vault, chaves, Cloud Guard)
├── cmp-prd
│   ├── cmp-prd-erp
│   └── cmp-prd-web
├── cmp-hml
└── cmp-sandbox

Não crie recursos no compartimento raiz. Separar a rede num compartimento próprio permite que o time de rede a administre sem acesso às VMs das aplicações.

02Políticas IAM

Allow group AdminsRede to manage virtual-network-family in compartment cmp-rede
Allow group AdminsERP to manage instance-family in compartment cmp-prd:cmp-prd-erp
Allow group AdminsERP to use virtual-network-family in compartment cmp-rede
Allow group Auditores to read all-resources in tenancy
VerboPermissão
inspectListar
readListar e ver detalhes
useUsar recursos existentes
manageTudo, inclusive criar e apagar

Em tenancies com domínios de identidade, o grupo pode precisar do nome do domínio na frente, como 'Default'/'AdminsRede'.

03Primeira VCN

ComponenteFunção
VCNRede virtual, por exemplo 10.110.0.0/16
Sub-rede públicaRecursos com IP público, como balanceador de carga
Sub-rede privadaServidores sem IP público
Internet gatewaySaída e entrada da internet para a sub-rede pública
NAT gatewaySaída para a internet a partir da sub-rede privada
Service gatewayAcesso a serviços da Oracle, como Object Storage, sem passar pela internet
DRGLigação com o datacenter (VPN ou FastConnect) e com outras VCNs
Security lists e NSGsRegras de firewall; prefira NSGs, aplicados por recurso

O assistente de criação de VCN com conectividade de internet já cria sub-redes pública e privada e os três gateways.

04Segurança e custo

  • MFA para todos os administradores; não use o usuário inicial no dia a dia.
  • Cloud Guard ativo para apontar configurações arriscadas.
  • O serviço de Auditoria registra as chamadas de API automaticamente; envie os logs ao SIEM se precisar de retenção maior.
  • Tags definidas (namespace de tags) para centro de custo e ambiente.
  • Orçamento com alerta em cada compartimento principal.

6.2 Envenenamento de dados

Data poisoning

O atacante manipula dados de treino, ajuste fino ou retreino para alterar o comportamento do modelo, seja degradando a qualidade, seja plantando um gatilho (backdoor) que só ele conhece.

Onde aparece
Coleta e preparação de dados; retreino com dados de produção
Sinais de detecção
  • Queda de acurácia ou mudança de comportamento após retreino sem causa aparente
  • Amostras anômalas, duplicadas ou com rótulo inconsistente no dataset
  • Fontes de dados novas ou sem dono entrando no pipeline
Mitigação
  • Registro de proveniência e linhagem de cada dataset e de cada execução de treino
  • Validação e revisão de dados antes de entrarem no treino, inclusive dados vindos da operação
  • Controle de acesso e integridade (hash) nos repositórios de dados
  • Comparação de comportamento entre versões do modelo antes de promover para produção
Exemplo
Amostras rotuladas de forma errada entram num dataset coletado da web e, meses depois, o filtro de fraude passa a liberar um padrão que deveria bloquear.
OWASP LLM 2025
LLM04 Data and Model Poisoning

6.3 Evasão

Evasion

O atacante altera a entrada, muitas vezes de forma imperceptível para humanos, para induzir o modelo a errar na inferência.

Onde aparece
Operação
Sinais de detecção
  • Entradas próximas da fronteira de decisão em volume incomum
  • Divergência entre o resultado do modelo e validações independentes
  • Mesmo usuário testando pequenas variações da mesma entrada
Mitigação
  • Teste adversarial antes do go-live e após mudanças
  • Validação e normalização de entrada
  • Segundo controle independente para decisões críticas (regra, outro modelo ou revisão humana)
  • Monitoramento de padrão de entrada por identidade
Exemplo
Pequenas alterações em pixels fazem um classificador de imagem ler errado uma placa ou um documento.
OWASP LLM 2025
Sem item direto; ver MITRE ATLAS

6.4 Inferência de pertencimento

Membership inference

O atacante descobre se um registro específico fez parte dos dados de treino, o que por si só pode revelar informação sensível sobre uma pessoa.

Onde aparece
Operação
Sinais de detecção
  • Consultas repetidas sobre registros específicos ou variações de um mesmo registro
  • Uso intenso de pontuações de confiança expostas pela API
Mitigação
  • Minimizar dados pessoais no treino
  • Reduzir a informação exposta na saída (não retornar probabilidades quando não for necessário)
  • Técnicas de privacidade no treino, como privacidade diferencial, quando aplicável
  • Limite de consultas e monitoramento por identidade
Exemplo
Testar se o prontuário de um paciente identificado foi usado para treinar um modelo clínico.
OWASP LLM 2025
LLM02 Sensitive Information Disclosure

6.5 Exfiltração de modelo

Model exfiltration

O atacante reconstrói uma cópia funcional do modelo enviando entradas e analisando as saídas. O ataque usa a própria interface legítima, por isso controle de acesso sozinho não resolve.

Onde aparece
Operação
Sinais de detecção
  • Volume alto e sistemático de consultas por conta ou chave de API
  • Consultas que varrem o espaço de entrada de forma regular
  • Uso de parâmetros que expõem detalhes internos (probabilidades, logprobs)
Mitigação
  • Throttling e cotas por identidade
  • Log de padrão de consulta com alerta para varredura
  • Expor apenas o necessário na resposta da API
  • Termos de uso e monitoramento de clientes de API
Exemplo
Um concorrente automatiza milhares de consultas a uma API pública de precificação e treina um clone.
OWASP LLM 2025
LLM10 Unbounded Consumption

6.6 Inversão de modelo

Model inversion

O atacante reconstrói dados de treino, ou partes relevantes deles, a partir das entradas e saídas do modelo.

Onde aparece
Operação
Sinais de detecção
  • Sondagem repetida com otimização de entrada
  • Saídas que se aproximam de exemplos reais do dataset
Mitigação
  • Minimização de dados no treino
  • Limitar detalhes expostos na saída
  • Limite de consultas e detecção de sondagem
  • Teste de extração de dados como parte do red team
Exemplo
Sondagem repetida de um modelo de reconhecimento facial para reconstruir a imagem de uma pessoa que estava no treino.
OWASP LLM 2025
LLM02 Sensitive Information Disclosure

6.7 Envenenamento direto do modelo

Direct model poisoning

O atacante adultera o próprio modelo (pesos, arquivo, configuração) durante o desenvolvimento ou a operação. Inclui modelo pré-treinado malicioso vindo de repositório público.

Onde aparece
Desenvolvimento, cadeia de suprimentos e implantação
Sinais de detecção
  • Hash ou assinatura do artefato diferente do registrado
  • Modelo carregado de fonte não aprovada
  • Arquivo de modelo que executa código ao ser carregado
Mitigação
  • Registro de modelos com controle de acesso e hash ou assinatura de cada artefato
  • Lista de fontes aprovadas para modelos pré-treinados
  • Preferir formatos que não executam código, como safetensors, em vez de pickle
  • Ambiente de desenvolvimento e treino segregado e protegido
Exemplo
Um arquivo de pesos alterado é baixado de um repositório compartilhado e vai para produção sem verificação. Em 2024, a JFrog relatou cerca de 100 modelos maliciosos no Hugging Face, um deles abrindo conexão remota ao ser carregado.
OWASP LLM 2025
LLM03 Supply Chain · LLM04 Data and Model Poisoning

6.8 Saída sensível

Sensitive model output

A saída do modelo revela parte de uma entrada anterior: dados de treino, documento do contexto, prompt de sistema ou prompt de outro usuário.

Onde aparece
Operação
Sinais de detecção
  • Dados pessoais ou confidenciais detectados na saída por DLP
  • Respostas que citam informação de outro usuário ou de outro tenant
  • Exposição do prompt de sistema
Mitigação
  • Filtro de dados sensíveis (DLP) na saída
  • Segregação de contexto por usuário e por tenant no RAG
  • Aplicar no RAG as mesmas permissões que o usuário tem no documento de origem
  • Não colocar segredos em prompt de sistema
Exemplo
Um assistente devolve trechos do registro de um cliente que estava no treino, ou um RAG mostra um documento que o usuário não tinha permissão para abrir.
OWASP LLM 2025
LLM02 Sensitive Information Disclosure · LLM07 System Prompt Leakage

6.9 Prompt injection

Prompt injection

Conteúdo elaborado pelo atacante acaba incorporado à instrução do sistema e provoca comportamento não previsto. Inclui a forma indireta: instrução escondida em e-mail, PDF, página web ou ticket que o sistema lê.

Onde aparece
Operação
Sinais de detecção
  • Instruções em texto oculto, metadados ou formatação em documentos recebidos
  • Agente executando ação fora do padrão logo após ler conteúdo externo
  • Tentativas de alterar o papel do modelo ou de revelar instruções
Mitigação
  • Tratar todo conteúdo externo como não confiável
  • Mínimo privilégio para o modelo e para o agente: o estrago fica limitado ao acesso
  • Aprovação humana para ações irreversíveis
  • Classificador de injeção como camada adicional, não como controle único
  • Red team com conteúdo injetado em cada canal de entrada
Exemplo
Uma instrução escondida dentro de um PDF faz a ferramenta de resumo enviar dados para fora. A CVE-2025-32711 descreveu um e-mail que levava um assistente corporativo a vazar dados do contexto sem clique do usuário.
OWASP LLM 2025
LLM01 Prompt Injection · LLM06 Excessive Agency

6.10 Saída com ataque de injeção

Output containing injection attacks

A saída do modelo carrega um payload que o componente seguinte executa: script renderizado em página, comando SQL, chamada de API ou link que dispara requisição com dados.

Onde aparece
Implantação e integração
Sinais de detecção
  • Saída contendo marcação, script, comandos ou URLs inesperadas
  • Requisições de rede disparadas pela renderização da resposta
Mitigação
  • Tratar a saída do modelo como entrada não confiável para o próximo sistema
  • Escape e sanitização antes de renderizar
  • Consultas parametrizadas, nunca SQL montado com texto do modelo
  • Bloquear carregamento automático de imagens e links externos na resposta
Exemplo
Texto gerado com script é exibido numa página sem escape e envia o cookie do usuário para o endereço do atacante.
OWASP LLM 2025
LLM05 Improper Output Handling

O que não tem cláusula própria

Agentes autônomos com uso de ferramentas e jailbreak não aparecem como itens separados. Prompt injection (6.9) e saída com injeção (6.10) são os mais próximos, e as orientações de governança, zero trust e mínimo privilégio continuam valendo. Para esses temas, complemente com o OWASP Top 10 para LLM (especialmente Excessive Agency) e o MITRE ATLAS. Veja Agentes e IAM.

Correspondência com o OWASP LLM Top 10 é leitura do autor, não consta da norma.
